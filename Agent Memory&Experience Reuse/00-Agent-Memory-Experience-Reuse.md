# Agent Memory & Experience Reuse

> [!abstract] 这组笔记研究什么？
> 如何让智能体从执行与评测中积累经验，并把经验转化为**更好的执行流程**或**下一次任务可用的记忆**。
> 当前收录 9 篇完整精读：AFlow、AWM、G-Memory、GPTSwarm、MemEvolve、EvolveR、EvoCF、NSI、ADAS。AFlow/AWM/G-Memory/GPTSwarm/MemEvolve/EvoCF/NSI/ADAS 改善模型外部系统；EvolveR 将外部原则记忆与 GRPO 参数训练结合。注意：GPTSwarm 的 RL 训练连边参数，EvolveR 的 RL 训练 LLM 策略参数。

## 先建立九个闭环

**AFlow：改进“以后如何做这一类题”。** 一个候选工作流在很多验证题上执行，评测结果指导下一次工作流修改。最后产物是可复用的执行程序。

**G-Memory：改进“下一道题能参考什么”。** 执行任务后保存案例、总结经验；新任务到来时检索相关记忆并放入智能体上下文。最后积累的是记忆库。

**AWM：改进“遇到相似子任务时有哪些操作套路可参考”。** 将历史网页操作提炼为抽象子流程；离线方式预先生成记忆，在线方式从已完成任务持续归纳。

**GPTSwarm：改进“团队内部谁应该参考谁”。** 用任务成绩更新跨 agent 连边概率；节点还可从历史成功执行中选择示例。最后产物包含外部数值策略，而基础 LLM 权重不变。

**MemEvolve：改进“系统应该怎样从经验中学习”。** 内层运行固定记忆程序并积累内容；外层诊断轨迹、生成新记忆程序、实际评测并选优。执行主循环和基础模型权重保持不变。

**EvolveR：改进“模型如何利用积累的经验做题”。** 离线将轨迹提炼为原则，在线主动检索原则与事实，随后用 GRPO 更新 LLM。经验文本默认屏蔽策略损失，不能把它理解成直接背下原则。

**EvoCF：改进“当前这一步团队还可以怎么行动”。** 将失败转成规则，结合检索结果生成和排序替代联合动作。它不训练模型参数，也不学习通信拓扑；规则主要供模型推理，不是形式化验证器。

**NSI：改进“可复用技能内部如何按状态执行”。** 从成功示范生成带条件、循环和动态绑定的技能图，由解释器实际运行；失败恢复成功后嫁接新分支。技能选择仍使用提示，技能内部控制不只是文字建议。

**ADAS：改进“由谁来设计解题系统”。** 将整个任务处理程序作为搜索对象，用模型生成代码、实际评分及完整设计档案迭代。档案主要服务外层设计者，不是内层任务检索经验库；没有模型参数训练。

## GPTSwarm 补上的比较维度

- **与 AFlow**：AFlow 搜索可执行工作流代码；GPTSwarm 在预设节点和候选边上学习连接概率。
- **与 G-Memory**：G-Memory 的图组织历史记忆；GPTSwarm 的图直接决定当前任务的信息流和执行依赖。
- **与 AWM**：AWM 归纳可参考的程序性记忆；GPTSwarm 的节点示例来自近期执行，未实现同等的语义检索体系。
- **证据边界**：填字实验的 20 题同时用于优化和评测，指标是 best-state word accuracy；GAIA 没有运行图优化。HumanEval 公开在线代码以完整测试成败标签筛选示例，需与题面内部测试区分。

## MemEvolve 补上的比较维度

- **内容与机制分开**：G-Memory/AWM 在既定机制内积累经验；MemEvolve 进一步搜索记忆机制本身的 Python 实现。
- **代码修改范围**：与 AFlow 的工作流程序不同，MemEvolve 生成器明确限制修改记忆模块，不改变核心 agent loop。
- **两种图分开**：CerebraFusion 的图连接经验条目；GPTSwarm 的图连接运行操作。前者当前检索沿语义相似边扩展，并不沿已保存的同任务边扩展。
- **评测边界**：WebWalkerQA/xBench 提供跨任务架构迁移证据；GAIA Level 1 参与进化，不能将总体成绩视为完全未见测试。费用接近不代表延迟降低。

## EvolveR 补上的比较维度

- **双阶段连接**：前五篇重在外部系统，EvolveR 把原则记忆与真正的 LLM 参数 RL 接起来；没有修改记忆模块源码或多 agent 拓扑。
- **自蒸馏含义**：轨迹到自然语言原则属于外部信息提炼，默认不是教师 logits 或原则全文的监督蒸馏。
- **图与检索边界**：结构三元组作为记忆内容返回，主要召回依旧是向量搜索，未展示跨原则图遍历；效用分数用于维护，不等于检索入口显式融合重排。
- **证据边界**：3B 完整系统 0.382，评测禁用经验检索后 0.340；并非经验已完全进入参数。离线总结训练轨迹会提供标准答案，需要隔离测试集。

## EvoCF 补上的比较维度

- **经验怎样改变行动**：规则既约束候选生成，也进入候选排序；与仅把经验放入上下文的方式相比，使用位置更明确。
- **优化粒度**：一个候选是当前一步“每个机器人各一个动作”，不是 AFlow 的完整工作流版本，也不是 GPTSwarm 的通信连边。
- **符号与反事实边界**：模型依据逻辑式规则推理排序，不模拟全部候选，不构成因果贡献估计或形式验证。
- **实验与成本**：正式版只报告 MAP-THOR；SR 0.72→0.84，而整次耗时 166.43→269.76 秒，步数下降不等于延迟降低。本次未定位到官方 EvoCF 实现，记忆隔离协议与部分数值口径仍不充分。

## NSI 补上的比较维度

- **经验到执行**：AWM主方法提供文字工作流；NSI将经验变成由解释器执行的技能程序。LLM仍负责状态抽取、路由和程序合成。
- **图的语义**：节点是变量操作、条件、循环、环境动作和终点，边是真正的控制流；不是多agent通信图或仅供检索的记忆图。
- **验证边界**：历史动作一致性和数据流检查不等于未知环境下正确性保证。公开ALFWorld候选按回放通过比例不下降接受，比论文严格覆盖扩张条件宽松。
- **结果与复现**：完整NSI在三个基准表现最好，但离线TextCraft78.5低于AWM92.5，在线修复后95.2；当前公开入口覆盖ALFWorld/TextCraft，未覆盖WebShop。完整成本未报告。

## ADAS 补上的比较维度

- **研究出发点**：将人工搭建提示词、反思和角色协作的工作，提升为可以被优化的系统设计任务；选择代码表示，再接入实际验证反馈。
- **档案的用途**：保存代码、设计说明和分数；标准实现整份输入外层元模型，没有向量 top-k 或 MCTS 节点选择。暂时低分的方案也可保存。
- **与 AFlow**：两者都搜索外部程序；AFlow进一步组织修改树、父版本选择和局部修改经验。ADAS不是基础模型RL或高阶递归优化器的实证。
- **证据边界**：MGSM公开默认按语言条目切分，本次审计发现同一底题译本跨验证/测试；ARC跨模型迁移使用测试成绩选择top3。预算未完全对齐，搜索档案并非每代变好。

## 与研究设想的对应

- **经验优化 Harness**：ADAS直接搜索任务处理程序；NSI直接归纳并修改技能程序；AFlow、GPTSwarm 与 MemEvolve 直接相关；G-Memory 提供可迁移的经验整理机制。
- **长期记忆与检索**：EvolveR 直接相关；G-Memory 与 AWM 直接相关：前者组织多粒度经验，后者提炼程序性子流程；AFlow 的经验主要服务搜索器。
- **多智能体协作**：EvoCF 直接修订联合动作与分工，但没有通信拓扑学习；GPTSwarm 直接学习信息连接；AFlow 可以改变调用与控制流程；G-Memory 可以给团队成员提供历史指导，但公开实现中角色投影是可选项。
- **RL / 参数蒸馏**：GPTSwarm 用 REINFORCE 优化外部连边；EvolveR 用 GRPO 更新 LLM。EvolveR 默认只对生成动作计算策略损失，经验仍作为外部上下文；取消经验 mask 的消融不等于标准知识蒸馏。
