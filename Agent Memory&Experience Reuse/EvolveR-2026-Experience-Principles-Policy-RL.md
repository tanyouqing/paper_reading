# EvolveR：从交互轨迹提炼原则，再训练会使用经验的策略

> [!abstract] 一句话说明作者做了什么
> 用 agent 自己的模型将成功/失败轨迹总结成可检索的策略原则，再让 agent 带着这些原则做新题，利用答案奖励与格式奖励，通过 GRPO 更新 LLM 参数。
> “离线自蒸馏”主要指轨迹变成外部原则；“策略进化”才更新模型。默认把召回的经验文本作为上下文，屏蔽其 token 的训练损失，并未直接把原则全文蒸馏进权重。

## 2. 出发点：有事实搜索，为什么还要经验搜索？

普通检索增强系统解决“缺少事实”：哪位人物、什么日期、哪个地点。但任务失败可能来自策略错误，例如只找到比较对象的一边就下结论，或把演员和角色混淆。

完整旧轨迹能提供案例，却很长、很具体；一句通用原则更容易迁移。仅把原则放入上下文又可能不够：模型未必会主动检索、正确理解和使用它。

本文将两种帮助分开：

| 类型 | 返回什么 | 作用 |
| --- | --- | --- |
| 事实知识 | Wikipedia 等外部语料段落 | 告诉模型世界中有什么 |
| 策略经验 | 从历史成败中总结的原则 | 指导模型怎样查、怎样比较、怎样避免错误 |

> [!example] 全文贯穿的教学例子
> 问“甲、乙哪位出生更早”。假设旧 agent 只搜到甲的出生年份，就凭印象回答，最终答错。可总结：“比较问题应先分别查到双方同类证据，再比较。”
> 后续关于检索、更新的题目与数字都是教学构造，不是论文中的实测样本。
> 原文 Figure 2 也用比较问题示意原则；附录 Table 18 的真实 rollout 是查询 Pinkerton 第一位女性侦探，最后答案为 Kate Warne。

这里希望留下的经验是可复用步骤，而不是只记住“甲比乙早”。

## 3. 输入、输出、状态和动作

任务输入是问答问题；最终输出是答案。中间历史包含模型生成的推理/动作，以及环境返回的经验和知识。

agent 的主要动作有：

- think：组织当前推理。
- search_experience：生成经验查询，由经验库返回原则。
- search_knowledge：生成事实查询，由外部检索器返回文档。
- answer：输出答案并结束。

论文排版使用带空格的动作名，代码标签实际使用下划线，例如 `<search_experience>`；经验返回包放在 `<experience>`，事实返回包放在 `<information>`。

**谁调用谁**：LLM 生成动作标签和查询 → 环境解析 → 调用对应检索服务 → 结果加入历史 → LLM 继续生成。不是原则自己执行动作，也不是一个固定脚本强制每题采用同一路线。

它主要是单策略 agent 的工具使用流程，没有多 agent 角色分配、通信图搜索或协作拓扑更新。

## 4. 一个完整周期：先做题，再整理经验，再改进策略

### 4.1 冷启动：先教会输出接口格式

用约 700 条来自 NQ/HotpotQA 训练集的交互轨迹，做短暂 LoRA SFT，稳定 think、search、answer 等格式。论文说目的在格式而非传授策略，但实际训练仍使用有内容的轨迹，不能据此证明模型完全没学到任务信息。

论文附录设置：3 epochs、学习率 1e-4、batch 16。冷启动和后续 GRPO 是两个阶段。

### 4.2 在线交互：主动查经验，也主动查事实

以比较题为例：

1. 模型发现需要比较两个实体。
2. 生成 search_experience 查询，询问比较任务的常见策略。
3. 返回“先收集双方同类证据”这类原则。
4. 模型据此生成事实查询，分别检索两个人的出生日期。
5. 阅读返回文档，继续判断是否需要补充搜索。
6. 生成最终答案，由标准答案评测本次结果。

经验查询和知识查询均默认 top-3。知识语料提供事实；经验本身通常不保证含当前题答案。

这一阶段收集带奖励的完整轨迹。训练时可以在 rollout 批次后更新策略，阶段描述不是指部署中每道题都临时训练一次模型。

### 4.3 离线整理：模型冻结，轨迹转成原则

agent 自己的模型读取轨迹与成败：

- 成功轨迹 → guiding principle，概括有效策略。
- 失败轨迹 → cautionary principle，概括需避免的错误。

一条原则包含自然语言描述与结构三元组。例如教学表示：

（比较任务，需要，双方证据）
（双方证据，应保持，同类属性）

这里的“自蒸馏”首先是**信息抽象与写入外部记忆**，不是经典“教师 logits → 学生损失”的参数蒸馏。离线总结时模型参数不更新。

**公开代码事实**：总结输入还拼入训练题的 Golden Answer，然后截取轨迹文本。因此是有标签训练数据支持的经验总结，不是纯靠 agent 自判。标准答案进入训练经验整理不自动等于测试泄漏；仍需严格保证只整理训练集，且原则没有夹带题目答案。

## 5. 原则怎样生成、去重、存储、检索和更新？

### 5.1 从候选原则到持久记忆

每批轨迹先总结，再去重：

1. 对同题多个候选原则，用模型判断语义等价，保留代表。
2. 从已有原则库按向量相似度召回候选。
3. 对相似度达到 0.85 的候选，再让模型判断是否表达同一核心规则。
4. 等价则合并来源轨迹，不重复添加；否则创建新原则。

论文 Eq.1 用相似度阈值简化表示；正文/附录和实现还有 LLM 等价检查，不能把“相似度超过阈值”直接当作最终合并条件。

存储分为原则与轨迹集合。原则带描述、结构、类型、使用/成功计数、来源轨迹 ID 等。实现可保留最近三条成功和两条失败来源；召回包装也可附案例。

### 5.2 查询时到底按什么排序？

公开 principle_client 的搜索入口对描述向量做 Milvus 相似度查询，取 top-k。ExperienceManager 再过滤重复、特殊标签及退化内容，组装返回包。

效用分数会被返回，影响清理并展示给模型；但本次核对的检索入口**没有显式把相似度与效用分数融合重排**。不能仅依据“高质量原则库”就说每次按成功率从高到低召回。

训练脚本默认：

- 返回原则描述与结构。
- 不把成功/失败完整轨迹写进返回上下文。
- 底层可以包装案例，不等于默认实验真的给模型看了案例。

### 5.3 三元组是否意味着图检索？

原则可以有“结构子图”式三元组，原则也关联来源轨迹。但实际召回主要是向量查询，结构作为文本提供给 LLM；没有在本次核对路径中看到跨原则图遍历或执行拓扑优化。

**有结构化数据，不等于有图搜索算法。**

### 5.4 效用分数如何更新？

$$
s(p)=\frac{c_{\mathrm{succ}}(p)+1}{c_{\mathrm{use}}(p)+2}
$$

c_use 是原则被本次轨迹召回的任务次数，c_succ 是这些任务中最终答对的次数。加一、加二让新原则初值为 0.5，避免零次使用出现无定义比例。

> [!example] 假设数字
> 一条原则被 8 个任务召回，其中 6 个答对，则 s=7/10=0.7。新任务召回后答错，更新为 7/11≈0.636。
> 这只能说明“召回这条原则时任务经常成功”，不能证明原则导致成功，也不能证明模型真的遵循了它。

代码对同轨迹里被召回的各原则统一记成败，没有逐条因果贡献估计。默认周期性移除 s<0.3 的原则。这是经验库维护，不是给每条原则单独做 GRPO。

长程保留的是经验库；当前推理和观察是任务上下文。没有独立的工作记忆控制器或记忆架构代码自改。

## 6. GRPO 到底训练哪些东西？

### 6.1 先把完整轨迹打分

任务奖励是标准化后答案精确匹配：

$$
R_{\mathrm{outcome}}=\mathrm{EM}(a_{\mathrm{pred}},a_{\mathrm{gold}})
$$

论文另加格式/行为塑形奖励：

$$
R(\tau)=1.0R_{\mathrm{outcome}}(\tau)+0.1R_{\mathrm{format}}(\tau)
$$

格式奖励不仅检查括号是否合法，也偏好一定的思考次数、搜索次数和同时使用经验/知识搜索。因而“经验搜索次数上升”部分受奖励设计影响，不能单独证明自发学会了有价值的检索。

代码对启用的奖励权重总和归一化；默认相当于将上式除以 1.1。额外的经验奖励、信息增益奖励虽然有实现，默认训练脚本权重为 0，不能说论文主配置额外用效用分数直接奖励 RL。

### 6.2 同一道题采八条轨迹，做组内比较

一批 128 道题，每题 G=8 条 rollout。成功、失败及不同行为得到不同总奖励，在同题组内标准化：

$$
\hat A_i=\frac{R_i-\bar R_q}{\sigma_q+\epsilon}
$$

R_i 是第 i 条轨迹奖励，均值与标准差在同一道题的八条轨迹内计算。超过组内平均的轨迹得到正优势，低于平均的得到负优势；不需要额外价值网络。

最终成绩无法指出哪一次检索真正必要，优势被分配给该轨迹中的模型动作 token，仍有粗粒度归因局限。

### 6.3 理论目标与代码损失

用教学记号整理 Eq.5：

$$
J=\mathbb{E}\!\left[
\sum_{t\in\mathcal A}
\min(r_{i,t}\hat A_i,\mathrm{clip}(r_{i,t},1-\epsilon_c,1+\epsilon_c)\hat A_i)
-\beta\,\mathrm{KL}
\right]
$$

r 是当前策略相对采样策略生成该 token 的概率比；A 是优势；clip 限制更新；KL 约束偏离参考模型。$\mathcal A$ 是模型生成位置，环境返回文本不属于本次策略动作。

实际优化最小化负目标。公开代码在 token 层计算概率比，对有效 loss mask 做 masked_mean，并实现负优势的 dual-clip 变体；因此不能将论文的 token 求和直接当作当前代码完整归约方式。默认 clip=0.2、KL 系数 0.001、学习率 1e-6。

它训练模型何时发起经验搜索、如何写查询、怎样利用返回内容继续推理与回答。不是训练向量数据库，也不是训练运行图连边。

### 6.4 为什么经验块屏蔽损失？

默认 `<experience>` 与 `<information>` 都是环境返回内容，所以这些位置不计策略损失。它们仍进入上下文，影响后续模型动作的梯度；“屏蔽观察 token 的 loss”不等于“这些文本对学习没有影响”。

附录 A.3 尝试取消经验块屏蔽：3B 平均分由 0.382 降为 0.371。它只能说明该种直接处理在该实验没有改善；不能推出所有参数蒸馏都无效。作者也提出可能需要另外的高质量原则监督目标，而不是将观察文本当策略动作做 GRPO。

## 7. 每一轮以后，什么改变、什么固定？

| 对象 | 变化方式 |
| --- | --- |
| 当前题轨迹 | 每次工具交互追加 |
| 原则库 | 离线提炼、去重、合并、更新分数、清理 |
| LLM 策略参数 | 在线轨迹经 GRPO 更新 |
| 记忆模块代码 | 固定，没有 MemEvolve 式源码进化 |
| 多 agent 运行拓扑 | 主方法没有这一优化对象 |

代码训练循环在设置间隔触发 reflection；默认 organize_interval=1，即按训练 step 批次组织经验，不是必须攒完整个数据集才总结。总结可使用 actor；实现也支持 API 调用路径，实际模型配置应记录。

本篇展示有限训练闭环，不等于无标签部署中无限持续自改，也不等于优化器能递归重写自身。

## 8. Benchmark 与评测协议

| 基准 | 任务形式 | 本文角色 |
| --- | --- | --- |
| Natural Questions（NQ） | 真实搜索问题的短答案 QA | 训练集用于学习/建库；域内评测 |
| HotpotQA | 跨文档连接事实或比较实体 | 同上；多跳问答 |
| TriviaQA | 开放域事实问答、含答案别名 | 域外评测 |
| PopQA | 实体属性/长尾事实问答 | 域外评测 |
| 2WikiMultiHopQA | 多实体、多关系链路问答 | 域外多跳 |
| MuSiQue | 组合多跳问题，要求连接多个证据 | 域外多跳 |
| Bamboogle | 不易靠一次简单搜索解决的问答 | 域外评测 |

主要指标为 EM，标准化后比较预测与真实短答案；部分分析报告 F1。不是 LLM 评价自由长文。这里“域外”指未用于该方法训练的数据集，不表示已证明基础模型预训练中完全没见过这些事实。

主实验 Qwen2.5-3B/7B，另分析 0.5B/1.5B。知识搜索沿用 Search-R1 类本地检索，经验 top-3，输入最长 8192、响应 1024。七套评测各自具体样本数、split/subsample 与全部 baseline 预算在本次已读说明中没有完整对齐表，复现不能自行补填或默认全量。

关键 baseline：直接回答、CoT、RAG、IRCoT、Search-o1、SFT、拒绝采样、R1、Search-R1。模型大小相同也不等于冷启动、训练轨迹和 rollout 预算完全相同，因此消融比跨方法大表更适合支撑机制归因。

## 9. 关键结果：哪些结论确实得到支持？

### 9.1 总体提高，并非每个数据集都赢

Table 1 的七基准宏平均 EM：

| 规模 | Search-R1-instruct | EvolveR | 差值 |
| --- | ---: | ---: | ---: |
| 3B | 0.325 | 0.382 | +5.7 个百分点 |
| 7B | 0.385 | 0.417 | +3.2 个百分点 |

3B 的 HotpotQA 为 0.324→0.373，MuSiQue 为 0.103→0.137。但 7B 的 2Wiki 为 Search-R1 0.414、EvolveR 0.395；不能说所有任务均优。Table 1 还显示 CoT 在小模型上很差，不能由此泛化为 CoT 普遍无用。

### 9.2 外部经验和 RL 是互补关系

Table 4，3B：

| 配置 | 平均分 |
| --- | ---: |
| 无原则、无 RL | 0.134 |
| 无原则、仅 RL | 0.325 |
| 原则+检索、无 RL | 0.357 |
| 经验条件 RL 训练后，评测禁用检索 | 0.340 |
| 完整系统 | 0.382 |

第四行不是“从来没有检索训练”。Table 3 明确说仅评测关闭经验访问。因此 0.340→0.382 支持测试时仍需经验；0.357→0.382 支持 RL 在经验系统上进一步有效。

正文把 0.340 误称为 RL-only，与表中真正 RL-only 0.325 不同。本笔记依据表与消融定义区分两者。

### 9.3 自蒸馏不在所有规模占优

Table 2：0.5B 自总结 0.150、GPT-4o-mini 教师总结 0.220；3B 自总结 0.382、教师总结 0.370。

说明自总结能力受模型规模影响。作者的“自生成原则与自身策略更匹配”是解释假说，不能由一组教师对照证明普遍的认知对齐机制。

### 9.4 SFT 对照与直接吸收经验

附录 Table 6，同样一批成功轨迹改用 LoRA SFT 得 0.357，GRPO 得 0.382。支持本配置 RL 的增量收益，不证明 SFT 原理上不能学习策略；两者优化目标、负例利用、参数化和训练配置不同。

经验取消 loss mask 得 0.371，低于标准 0.382，也说明默认方法依旧将原则当外部上下文。

### 9.5 原则质量与规模

人工检查 100 条原则（Table 9）：高分层可执行且正确占 82%，仍有 8% 错误/误导；低分层“正确但空泛”占 50%。评分有筛选价值，但不是正确性保证，样本量也有限。

Table 10 从约 4.2k 到 49.9k 原则：top-3 检索约 0.04→0.20 秒；平均分在 45k 时 0.410，49.9k 时回落 0.387。库大小随训练同时变化，不能把它当固定模型下“增加记忆数量”的纯控制实验，更不能说记忆越多必然越好。

论文主结果未给出多随机种子误差条，本次不把单次差异写成已证明统计显著。

### 10.2 报告的硬件与成本

附录 A.1：3B 完整冷启动+RL 约 **39.4 小时，8×A100 80GB**。按机器规模乘时长约 315.2 A100 卡时，是基于报告的计算换算，不是新的实测。未报告完整训练的美元费用和所有服务单独占用。

约 14k 原则 top-3 召回约 0.06 秒，只是检索延迟，不是端到端生成、离线总结或全部工具链成本。

官方提供 3B 权重、处理数据链接和脚本；还需部署 embedding、Milvus 服务及本地事实检索索引。完整复现实验并非低成本单卡任务。可以先用权重做推理/记忆机制实验，但更低配置的显存与时长本次没有实测，不作保证。

## 11. 创新与研究关系

依据公开设计重建逻辑：事实工具不能修复策略性错误 → 完整案例冗长且难迁移 → 自总结成原则 → 去重和评分维护质量 → 主动检索指导行为 → 用奖励优化经验条件策略 → 新轨迹反过来继续总结。此为设计逻辑重建，不是作者未公开的心理过程。

与 Search-R1 的关键增量是增加经验检索与生命周期；与静态反思记忆相比增加模型策略训练。实际证据支持检索和 RL 互补，但没有完整证明每个原则的因果效用或全部经验已参数化。

| 研究设想 | 关联 |
| --- | --- |
| 经验优化 Harness | 可迁移：固定框架下组织经验，没有源码进化 |
| 长短期记忆与检索 | 直接相关：持久原则库与当前交互上下文 |
| 单 agent 执行 | 直接相关：经验/知识双检索 |
| 多 agent 运行图 | 未覆盖：没有协作拓扑、角色或路由图学习 |
| RL 强化 | 直接相关：GRPO 更新 LLM 参数 |
| 参数蒸馏 | 部分探索：默认无直接原则监督蒸馏，取消 mask 消融也不是标准知识蒸馏 |

**小实验建议，非论文结论**：固定同一冷启动模型和训练题，比较无经验 RL、固定原则提示、经验条件 RL 三组；各自测试时再切换有/无检索。预算对齐后统计 EM、检索次数、token、无效原则率；另用同一模型和不同库规模，隔离记忆数量效应。先验证“会使用经验”和“记住答案”的区别。

## 12. 阅读路线与三个问题

先读 Figure 2 与 §3.2，确认两类搜索和记忆生命周期；再读 Eq.2 与评分代码，理解它不是因果效用；然后读 §3.3、附录 A.1、A.3，分清 GRPO 与观察 loss mask；最后读 Tables 3/4/6 和代码默认返回项，再看完整主表。

1. 同一次轨迹召回多个原则，怎样更准确地分配贡献，而非全体统一记成败？
2. 如何让原则只保留可迁移策略，避免答案泄漏、过度具体化和空泛建议？
3. 若要把原则真正蒸馏进参数，应该采用何种监督目标与质量过滤，才能在关闭经验库后仍保留收益？
