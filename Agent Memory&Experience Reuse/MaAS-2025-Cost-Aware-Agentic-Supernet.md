# MaAS：按题目选择运行流程，并用成本约束训练控制器

> [!abstract] 一句话抓住工作
> 作者训练一个小型控制器，根据题目从算子库选择不同长度与组合的执行流程；流程真实运行后的答题分数和成本，反过来训练控制器，并可让 LLM 修改算子。
> 输入：带答案的训练任务、预置算子及描述、成本设置。训练产物：流程选择器参数与算子程序/提示词。新任务输出：按题目组织并执行流程后的答案。
> 基础 LLM 权重冻结；有数值训练的是外部控制器。算子“文字梯度”是模型生成修改建议/代码，不是对自然语言或 LLM 权重反向传播。

> [!info] 阅读范围与去重
> 本次阅读 PMLR 正式 PDF 全部 19 页，包含方法、主实验及附录 A–D；静态核对官方代码版本 `987f3c1bc9a96e844fe090db3791446e3ef0f5c7`（2026-10-28），覆盖控制器、采样、代码 loss、三个数据集执行模板、评分器与文字修改路径。没有运行 API、付费复现实验或验证公开权重。

## 2. 出发点与研究逻辑：为什么不再寻找一套最佳工作流？

### 2.1 一个贯穿例子

> [!example] 教学例子，不是论文真实实验轨迹
> 任务：“实现一个 Python 函数，返回整数列表中第二大的不同元素；不足两个不同元素时返回 None。”
> 输入 `[4,4,1]` 应返回 1；`[4,4]` 应返回 None。
> 本例只为解释模块和信息流，未声称模型实际产生过下述错误或路由。

固定的简单生成器可能把“第二大”理解成排序后倒数第二项，于是对重复元素处理错误。固定的复杂系统可以每题都多生成、测试、反思和集成，但对简单函数也付出全部成本。

作者 §1 提出两个问题：

1. **同一领域内难度不同**：简单算术和困难数学不应必然使用同样多的模型调用。
2. **不同领域需求不同**：网页搜索、文件处理和编程题需要不同算子；一套固定复杂流程可能同时昂贵又不合适。

于是研究问题从“哪套流程总体最好”变为：**能否学到一个按题目选择流程的规则，在正确性和成本之间取舍？**

### 2.2 方法选择为什么顺着出现？

- 需要许多不同流程，但不想为每题重新做完整的程序搜索 → 训练一个可复用控制器。
- 流程由已有生成、反思、测试等模块组成 → 将这些模块作为“算子库”。
- 题目不同，组合应该不同 → 给控制器输入题目语义表示。
- 算子执行经过黑盒 API，不能对答案正确率直接求普通梯度 → 根据采样流程的执行反馈训练选择器。
- 只改组合还不够 → 另让 LLM 提议算子提示词、温度或结构修改。
- 想减少不必要的深度 → 在选择空间加入 Early-exit。

> [!note] 研究逻辑重建
> 上述顺序依据公开动机与机制组织，不代表作者未公开的心理过程。关键是改变优化对象：从一个工作流转向一个条件化的工作流分布。至于“是否真正更泛化、成本是否算全”，仍要看实验和实现。

## 3. 架构与输入输出

### 3.1 四个关键对象

| 对象 | 具体是什么 | 常见误解 |
| --- | --- | --- |
| 算子 Operator | 一段封装模型调用、提示词或工具操作的程序；内部可能多次调用 LLM | 一个算子一定等于一个 agent 或一次 API |
| 超网 Supernet | 算子库加上可学习的多层选择规则，代表许多潜在流程 | 必须先运行整张巨大网络 |
| 控制器 Controller | 根据题目和此前选中算子，输出下一层选择分布的小型神经网络 | 基础大模型被参数微调 |
| 采样出的流程 G | 当前题实际执行的算子及顺序/数据传递 | 搜索历史树、记忆图 |

“超网”一词借鉴神经架构搜索。这里共享和选择的是 agent 算子，不能把它理解成训练所有基础 LLM 的共享神经网络权重。

### 3.2 执行与优化分开

| 阶段 | 输入 | 做什么 | 输出 |
| --- | --- | --- | --- |
| 优化 | 训练题与参考答案、算子、成本反馈 | 采样并执行流程，更新控制器；可修改算子 | 控制器参数、算子实现/提示词 |
| 推理 | 新题、已训练控制器与算子 | 选择流程，执行模块 | 新题答案 |

论文控制器主要依据题目与先前选定算子进行选择。核对代码在 `Workflow.__call__` 开头一次调用控制器，先形成各层选择，再执行算子，**没有在每一步看见实际回答质量后再决定下一层**。

因此，“简单题更早结束”是学到的路由倾向；不是内置验证器确认答案正确后，才授权停止。

### 3.3 提供了哪些基础能力？

附录 B.1：CoT、LLM-Debate（三位辩论者、最多两轮）、Self-Consistency（五条推理）、Self-Refine（最多五次）、Ensemble、Testing、ReAct、Early-exit。

公开可运行入口只支持 GSM8K、MATH、HumanEval：
- 通用注册项为 Generate、GenerateCoT、MultiGenerateCoT、ScEnsemble、SelfRefine、EarlyStop；
- 数学加入 Programmer；编程加入 Test；
- 当前 MultiGenerateCoT 实现生成三个候选，不能按论文 Self-Consistency 的五条设置反推代码；
- 编程 Generate 与 GenerateCoT 在该版本实现基本一致，都用 code_fill，名称差异不自动等于行为差异。

## 4. 方法：一题怎样选择、执行和学习？

### 4.1 先将题目与算子变成向量

论文附录 B.2：LLM 根据算子程序生成描述和接口；MiniLM 编码描述。题目也编码成向量。控制器利用这些表示学习“这种题适合哪些操作”。

公开编码器为冻结的 `sentence-transformers/all-MiniLM-L6-v2`，向量为 384 维；每层用小型线性投影到默认 32 维，归一化后计算匹配分数，再 softmax。

这允许控制器按描述处理新的算子，但**语义上相似不等于适用条件已验证**，softmax 分数也不是该算子的任务成功概率。

### 4.2 按层选择，可一层多算子，也可以退出

论文 Eq.7 的结构可写为：

$$
Q_\phi(G\mid q)=\prod_{\ell=1}^{L}
\pi_\phi(V_\ell\mid q,V_{<\ell})
$$

- q：当前题；
- G：当前题的流程；
- Vℓ：第 ℓ 层选中的算子集合；
- V<ℓ：此前选中的算子；
- φ：控制器可训练参数；
- L：最大深度，主设置 4。

这表达按层条件化选择，不是逐 token 生成策略。Early-exit 终止后续层构建，最大层数不是调用次数上限：某算子内部可以调用多个模型。

论文 Eq.9 描述将激活分数降序排列，累计到阈值；代码则按概率无放回随机抽样，直到所选算子原始概率之和达到 0.3。两者不能混写为完全相同的算法。

### 4.3 回到贯穿例子：选中流程后谁调用谁？

一种**假设的路由**是：

`Generate → Test → SelfRefine → EarlyStop`。

生成器接收原题并给出函数；Test 在允许的内部测试上执行，发现 `[4,4]` 的返回错误；修订器读取原题及相关输入修复实现，最后输出一个程序，外部评测器用独立参考测试评分。

具体输入传递取决于算子实现，不应只从图名断言所有失败日志都传到了每个后续节点。例如公开 SelfRefine 主接口读取问题和当前解，不自动获取完整环境事件。

如果换成“一加一”的题，控制器可以选择较短路径；复杂题可能选多候选和集成。这里假设了可能的选择，没有给未经实际模型运行的概率数值。

### 4.4 反馈如何训练控制器？

论文 Eq.5 最直观：

$$
\max_\phi\;
\mathbb{E}_{(q,a)\sim D,\;G\sim Q_\phi(\cdot\mid q)}
[U(G;q,a)-\lambda C(G;q)]
$$

- D：训练题及参考答案；
- U：执行 G 后得到的任务表现，例如答对为 1、答错为 0；
- C：流程执行成本，论文以 token 成本表述；
- λ：效果与成本的取舍系数。

直觉：正确但过度昂贵的组合不应无限增加概率；同等正确率时偏向较便宜的组合。这个目标约束预期成本，**不是每题严格 token 上限，也不是对新题可靠性的保证**。

论文 Eq.10–11 另以答案概率和经验贝叶斯 Monte Carlo 写更新。其中权重：

$$
m_k=
\frac{p(a\mid q,G_k)}{\sum_i p(a\mid q,G_i)}
-\lambda\frac{C(G_k;q)}{\sum_i C(G_i;q)}
$$

k 指采样的某个流程；两项分别在候选内归一化质量与成本。原文 Eq.11 写为对流程概率求导的加权和，而非标准 log-policy 形式；不能悄悄把它替换成 GRPO 或说代码逐字实现此式。

**公开代码实际最小化**（`benchmark.py`）：

$$
L_{\mathrm{code}}
=-\frac1B\sum_{j=1}^{B}
\ell_j\,[r_j-3c_j],
\qquad
\ell_j=\sum_{\text{已选择算子}}\log p_\phi(O)
$$

- B：当前 batch 的题数，入口默认 4；
- rj：该题评分；
- cj：代码从共享累计 API 费用差分得到的成本；
- ℓj：所选算子的 log-softmax 分数之和；
- 3：当前代码固定成本权重，不是论文 λ 的同一数值或同一量纲。

代码 `loss = -(logprobs * utilities).mean()`，随后 Adam 更新 `controller.parameters()`。没有 PPO 裁剪、GRPO 组内标准化、价值网络或基础 LLM 的 token loss。

这是外部选择策略的策略梯度风格训练。但当前代码的 ℓj 未完整包含无放回抽样条件概率的重归一化，也没有完整记录首层强制替换的采样概率；因此不应声称是严格无偏的原始采样策略梯度估计。

### 4.5 算子怎么修改？“文字梯度”是什么？

论文 §3.3/附录 B.3：LLM 输出关于提示、温度和算子内部节点结构的修改，可生成完整 Python 算子。

它叫 textual gradient，是用改进建议类比梯度；实际不是对字符串求导，不训练 LLM 参数。

公开入口默认 `--is_textgrad False`。开启后，现有主路径监测不同重复轮的平均分是否下降，再随机抽一个提示词，让 LLM 改写。独立 `textual_gradient.py` 还能输出算子 JSONL，但不能因此声称主入口已自动完成所有程序生成、注册与回归验证。

## 5. 记忆、图与学习对象：哪些实际存在？

| 内容 | 本文做了什么 |
| --- | --- |
| 当前任务上下文 | 维护当前解、候选解列表，供后续生成/反思/集成 |
| 经验长期库 | 没有 G-Memory/AWM 式轨迹到经验的检索库 |
| 存储 | 控制器 checkpoint、算子文件、提示词、分数与失败日志 |
| 新题读取 | 控制器参数和算子描述，不是先检索相似历史任务轨迹 |
| 图的作用 | 决定当前题的操作组合、深度和数据传递 |
| 参数训练 | 外部控制器训练；MiniLM 和基础 LLM 冻结 |
| 蒸馏 | 未做模型参数蒸馏 |
| 递归自改进 | 可更新算子，未证明元优化器和验证器自身递归进化 |

论文将 G 定义为 DAG；公开任务模板实际按层和所选顺序串行调用，用 `current_solution`、`solutions` 传递结果。它没有展示任意节点对之间自由学习通信边的通用实现。

## 6. Benchmark 与评测协议

主实验在数学、代码、工具三类任务。表 6 的具体切分如下：

| Benchmark | 输入/交付 | Train/Test | 指标与验证 |
| --- | --- | ---: | --- |
| GSM8K | 数学应用题 → 数字答案 | 264/1055 | Accuracy；代码提取末尾数字并以 1e-6 容差比较 |
| MATH | 困难竞赛数学 → 最终数学答案 | 119/486 | Accuracy；代码用 boxed 提取、数值/SymPy 等价检查 |
| MultiArith | 多步算术文字题 → 数值答案 | 150/600 | Accuracy；当前公开 evaluator 未提供完整入口 |
| HumanEval | Python 函数题面 → 函数实现 | 33/131 | pass@1；外部执行正式测试 |
| MBPP | 简短编程需求 → 程序 | 86/341 | pass@1；当前公开 evaluator 未提供完整入口 |
| GAIA | 搜索、文件、多模态综合任务 → 答案 | 94/372 | Accuracy；当前公开 evaluator 无完整 GAIA 工具与评分入口 |

论文称大体 Train:Test=1:4。它不是各基准官方完整训练/测试协议，不能直接与标准排行榜混比。pass@1 指最后提交一个程序，不表示内部只调用一次模型。

主模型 GPT-4o-mini-0718；温度 1；L=4、K=4、阈值 0.3；λ 在 {0.001,0.005,0.01} 中设置。跨模型用 Qwen2.5 和 Llama3.1 API；原文 Qwen 部分行同时出现 70B 与 72B，保留版本命名冲突，不自行统一为另一模型。

### 6.1 数字/协议冲突不能略过

- 引言有“seven benchmarks”和 SVAMP；正式主表/表 6 实际六套，使用 MultiArith。本笔记以具体主表为准。
- 正文称 MATH 取四类 level-5 共 617 题，但表 6 的 119+486=605，未说明少的 12 题如何处理。
- MultiArith 表 6 合计 750；当前没有对应数据清单可核对，不能自行补出额外样本的来源或划分规则。
- 表 1 声称统一 GPT-4o-mini，但附录 C.2 的 LLM-Blender 明确混入 Qwen/Llama。因此该基线并非严格同底座。
- AFlow 在这里的优化模型被限制为 GPT-4o-mini；原 AFlow 使用 Claude-3.5-Sonnet 优化。比较反映本文设置，不代表原论文最大效果。
- 论文未清楚报告主表每个数字的独立搜索种子数和置信区间；难以判断 0.5 个百分点级差异是否稳定。

### 6.2 内部测试与正式测试

公开 HumanEval Workflow 将题面与入口函数传给内部 Test，Test 从 `humaneval_public_test.jsonl` 读用例；外部 Benchmark 在流程返回后再执行 `data["test"]` 评分。

当前仓库未包含所需 JSONL 数据，无法核对 public_test 是否完全与正式测试隔离。只能确认代码读取不同路径，不能据此宣布不存在泄漏，也不能断言 public_test 就是隐藏测试。

## 7. 关键实验：成绩、消融与成本分别支持什么？

### 7.1 主表

表 1，单位 %：

| 方法 | GSM8K | MATH | MultiArith | HumanEval | MBPP |
| --- | ---: | ---: | ---: | ---: | ---: |
| Vanilla | 87.45 | 46.29 | 96.85 | 87.08 | 71.83 |
| GPTSwarm | 89.14 | 47.88 | 96.79 | 89.32 | 77.43 |
| AFlow | 91.16 | 51.28 | 96.22 | 90.93 | 81.67 |
| MaAS | **92.30** | **51.82** | **98.80** | **92.85** | **82.17** |

相对 AFlow，MATH +0.54、HumanEval +1.92、MBPP +0.50 个百分点。摘要的 16.89% 是相对某些特定基线和口径，不是每个任务相对强基线均提升 16.89 个百分点。PMLR 页面摘要又为 0.54–11.82%，与正式 PDF 的 0.54–16.89% 不同；优先引用具体表格。

表 2 GAIA 总体：AFlow 8.00、GPTSwarm 16.33、TapeAgent 16.61、MaAS 20.69。体现不同任务的路由可能有价值，但缺完整代码和等预算协议，不把它直接解释为确定的泛化优势。

### 7.2 最有解释力的消融：成本项与退出算子

表 4，费用单位 10^-3 美元/题：

| 版本 | HumanEval分数 | 费用 | MATH分数 | 费用 |
| --- | ---: | ---: | ---: | ---: |
| 完整 | 92.85 | 1.01 | 51.82 | 0.86 |
| 无算子文字更新 | 90.17 | 0.90 | 48.23 | 0.84 |
| 无 Early-exit | 91.44 | 1.67 | 51.53 | 1.04 |
| 无成本项 | **92.94** | 1.38 | 51.19 | 1.28 |

- 无成本项 HumanEval 略高 0.09，但更贵，说明“成本约束”是在做取舍，不是所有指标同时提高。
- 移除退出后成本上升而准确率并未改善，支持限制不必要深度有意义。
- 无文字更新分数下降，支持算子改善的贡献；但无法由此确定是提示词、温度、结构哪一个单独起作用。

### 7.3 训练/推理成本必须分开

表 3 MATH：

| 方法 | 优化输入/输出token | 优化费用 | 优化时长 | 测试输入/输出token | 测试费用 | 测试时长 |
| --- | --- | ---: | ---: | --- | ---: | ---: |
| AFlow | 33,831,239 / 29,051,840 | $22.50 | 184分 | 2,505,944 / 2,151,931 | $1.66 | 23分 |
| MaAS | 3,052,159 / 2,380,505 | $3.38 | 53分 | 1,311,669 / 853,116 | $0.42 | 19分 |

以上是论文历史设置下的总量，不能把 $0.42 当每题成本。比值计算：
- 费用：优化约 15.0%，测试约 25.3%；
- 总 token：优化约 8.64%，测试约 46.5%。

因此“仅用25%推理成本”不能自动改写成“仅用25% token”。论文 λ 的质量减执行成本目标不等于自动最小化所有生命周期开销；控制器拟合、文字更新、embedding、重试及工具成本需要逐项确认。机器配置和并发完整细节未知，墙钟比较受实现影响。

### 7.4 迁移证据与可靠性边界

表 8：
- MATH→GSM8K：MaAS 92.80，AFlow 91.95；
- GSM8K→MATH：MaAS 51.02，AFlow 49.39；
- HumanEval→MATH：MaAS 50.27，AFlow 47.15。

表 7：GPT-4o-mini 的控制器/超网迁移到其他模型后，在 HumanEval/MATH 提升；例如 Qwen HumanEval 85.60→90.14。模型标签的 70B/72B 冲突需保留。

这些是**整体任务分布上的平均成绩**，未校准到某一题、某个技能或某种前提变化下的成功概率。新增 Debate 算子的实验主要展示激活分布，没有完整报告“未知技能在新状态下可靠”的验证证书。

### 8.1 重要实现限制（静态证据，不声称已重跑）

1. **采样与条件化范围不同**：代码无放回随机采样；后续层只使用前一层第一个算子的 embedding，不是论文所有此前层的汇总。
2. **首层强制生成**：若首层未抽到 Generate，会替换为 Generate；抽到 EarlyStop 时替换生成并停止构建。代码加的 -1.5 是常数，不会独自产生对原退出选择的梯度。
3. **GSM8K 梯度断开**：该模板用 `log_probs_layers[layer_idx].item()` 累加返回 Python float，而训练循环调用 `torch.stack(logprobs)`。照此路径不能直接完成预期的控制器训练；须修改后验证，不可说默认一键复现。
4. **K 的语义不同**：公开 `--sample` 传入整个训练集的 repetitions，并在 batch 间更新参数，不等于对同一题、同一固定策略采 K 个候选后按 Eq.11 归一化。
5. **文字更新调用不匹配**：触发分支调用 `update_prompt_in_file(prompt_name,response["prompt"])`，定义却要求 `(log_path,prompt_name,prompt_content)`；到达此处会参数不足。默认关闭该路径，不能靠README命令证明联合算子进化可运行。
6. **固定额外执行**：HumanEval 无论选什么，末尾都再执行 Test，失败还补一次 CustomCodeGenerate；MATH 在所选层之前固定执行 Programmer 和答案修订。Early-exit 不等于只剩一个模型调用，论文图示短路径不能替代成本审计。
7. **成本归因**：并发任务共享流程LLM的累计费用，返回的累计 cost 再按结果顺序差分。异步完成顺序与题目顺序未必一致，可能使单题成本与梯度权重错配；需记录调用ID和每题独立费用核验。
8. **“测试通过”可能空检**：内部测试加载器对若干入口返回空字符串，`for test_case in test_cases` 不运行循环即可返回“no error”。公开数据缺失，不能断言每题 Test 都提供有效验证。
9. **配置/数据覆盖**：主 evaluator 只有三套基准，没有完整 MBPP、MultiArith、GAIA 的对齐复现入口；所需 JSONL 及标准测试隔离需要另行准备。

这些缺口限制当前公开实现的直接可复现性，但不自动证明论文全部结果无效。应区分“论文所报告系统”和“当前发布版本能否重现”。

### 8.2 资源

基础 LLM 经 API，无基础模型训练GPU需求；小型控制器可用CPU/GPU，MiniLM冻结。论文未给训练机器/GPU型号、内存、完整并发及现代价格，标未知。不能把“无需训练大模型”说成“没有训练或API成本”。

仓库有 HumanEval 的部分控制器权重文件，但命名/加载路径需核对，不能假设已覆盖当前 `<dataset>_controller_sample4.pth` 加载约定。不要加载未知pickle权重来做本次静态阅读验证。

## 9. 与已有工作及当前想法的关系（简短）

| 维度 | 对应 |
| --- | --- |
| 经验优化 Harness | 直接：用执行反馈优化选择器与算子 |
| 长短期记忆/检索 | 当前解上下文存在；无长期轨迹经验检索库 |
| 单智能体执行 | 一个算子可为单模型调用，也可多次调用 |
| 多智能体运行图 | 直接：题目条件化选择组合与深度，但代码非任意边全自由搜索 |
| RL/参数蒸馏 | 外部控制器策略梯度风格训练；无基础LLM参数RL与蒸馏 |
| 迁移可靠性 | 有平均迁移实验，无技能适用范围或成功率校准 |

与 ADAS/AFlow 比，独特之处是从静态程序转向题目条件化的路由；与 GPTSwarm 比，强调按题选择算子与深度，而不只学习一个候选边集合的总体连接倾向。它并不首次提出所有形式的图分布或成本感知优化，作者的“首次范式”主张应按具体条件理解。

对用户已收敛的“低成本验证修改后技能在新任务变体上的可靠性”：MaAS 的算子选择概率不是成功率；在预算内选择测试、修复后独立变体验证、失效拒绝复用均未被本文完成。可借鉴成本目标，不应将其当成已解决统计可靠性问题。

**小实验建议，非论文结果**：固定模型、算子、总预算，比较固定流程、按题路由、加入低预算独立验证的路由；对未见输入/前提变体测成功率、总token、错误接受率及可靠性校准。先做数据隔离和有效测试审计，再引入复杂技能修复。
